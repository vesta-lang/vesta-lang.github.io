## 说明

将 控制寄存器 (CR0, CR2, CR3, CR4, 或 CR8) 的内容移动到 通用寄存器 或 通用寄存器 的内容移动到 控制寄存器. 这些指令的操作数大小在非64位模式中总是32位,无论操作数的大小属性如何. 在64位能处理器上,在64位模式的0外执行MOV到CR,将控制寄存器的上32位执行. (见Intel(R)64和IA-32架构软件开发者手册第3A卷第2章中的"控制注册",详细描述控制注册中的旗帜和字段. ) 本指令只有在当前特权级别为0时才能执行.

在 操作码 级别上, ModR/M 字节中的 reg 字段指定了哪个控制登记册是加载或读取的. Mod字段中的2位被忽略. R/m 字段指定装入或读取的 通用寄存器 。 CR0,CR3,和CR4中的一些位点是保留的,必须用零写. 试图在 CR0 [31:0] 中设置任何保留位元的尝试被忽略 。 试图在 CR0 [63:32] 中设置任何保留位点,导致一般保护例外 #GP(0). 未启用PCID时,不使用CR3中的2:0和11:5的位元,并忽略设置它们的尝试. 关于CR3中保留的位元的处理,见下段. 试图在 CR4 中设置任何保留位元的结果为 #GP(0) 。 在Pentium 4,Intel Xeon和P6家族处理器上,CR0.ET在CR0的任何负载后仍然被设置;试图清除这一位没有影响.

通常,MAXPHYADDR是CPUID.80000008H:EAX[7:0]中列举的值. 然而,如果IA32 TME ACTI-VATE[0]=1(表示TME已经配置),则当一个逻辑处理器在安全仲裁模式(SEAM;见Intel(R)64第35章和IA-32架构软件开发者手册,第3卷)之外时,MAXPHYADDR的值被IA32 TME ACTI-VATE[39:36]降低;该值在SEAM中不降低. 试图在 CR3 [63:MAXPHYADDR] 中设置任何保留位,结果为 #GP(0).

在某些情况下,这些指令具有在TLBs和page-结构缓存中取消条目的副作用. 见5.10.4.1节,"使TLBs和Page-Structure Caches无效的操作",详见Intel(R)64和IA-32架构软件开发者手册第3A卷.

以下副作用针对Pentium 4,Intel Xeon,以及P6处理器家族: 当修改注册CR0中的PE或PG时,或者在注册CR4中的PSE或PAE时,所有TLB条目都被冲走,包括全局条目. 软件不应依赖于所有Intel 64或IA-32处理器中的这一功能.

在64位模式下,指令的默认操作大小为64位. REX.R的前缀必须用于访问CR8. 使用REX.B可以访问额外的登记册(R8-R15). REX.W前缀或66H前缀的使用被忽略. 使用 REX.R 前缀指定除 CR8 以外的寄存器会导致无效-操作码 例外. 参见本节开头的汇总图,用于编码数据和限制.

如果 CR4.PCIDE = 1, 源操作数 到 MOV 到 CR3 的比特 63 确定指令是否使 TLBs 和 page-结构缓存中的条目无效(见第5.10.4.1节,"使 TLBs 和 Page-Structure Caches 无效的操作",Intel(R) 64 和 IA-32 Architectures Software开发者手册,Volume 3A). 该指令不修改 CR3 的比特 63,该比特是保留且总是0.

请参看Intel(R)64和IA-32架构软件开发者手册第3C卷第27章中的"VMX非root操作中的改变指令行为",以了解VMX非root操作中此指令行为的更多信息.

## 行动

```text
DEST := SRC;
```

## 受影响的旗帜

OF,SF,ZF,AF,PF,和CF旗没有定义.
