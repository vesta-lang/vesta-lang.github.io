## 说明

使用直接存储操作,将源操作数(第二个操作数)中的双字整数移动到目标操作数(第一个操作数). 源操作数是一个通用注册. 目标操作数是一个32位的内存位置. 在64位模式下,指令的默认操作大小为32位. 使用REX.R前缀可以访问额外的登记册(R8-R15). 使用REX.W前缀将操作提升到64位. 参见本节开头的汇总图,用于编码数据和限制.

直接存储是通过将(WC)内存类型协议组合起来的写入数据执行的. 使用此协议,处理器不会将数据写入缓存层级,也不会将相应的缓存行从内存中提取到缓存层级中. 如果目的地地址是缓存的,则该行会被写回(如果修改),并从缓存中失效,在直接存储之前. 与拥有非时空提示的存储,允许目的地的未标记(UC)和被写入保护的(WP)内存类型凌驾于非时空提示之上不同,直接存储总是跟随WC内存类型协议而不管目的地地址内存类型(包括UC和WP类型).

与WC商店和带有非时序提示的商店不同,直店可立即被逐出写作组合缓冲器,因此不会与较年轻的商店(包括直店)合并到同一地址. 保存在写字缓冲器中的老式WC和非时空商店可以与较年轻的直接商店合并到同一地址. 相对于其他店铺,直接店铺的订货量微弱. 想要更强烈订单的软件应当在直接商店之前或之后使用栅栏指令(MFENCE或SFENCE)来执行所想要的订单.

MOVDIRI向4字节边界对齐的目的地(如果与REX.W前缀使用8字节边界)发布的直接存储保证4字节(与REX.W前缀使用8字节)书写完成原子化. 这意味着数据以单一的未分割的4字节(或8字节)写成交易到达目的地. 如果目的地不与写字大小对齐,则MOVDIRI发行的直店分两部分到达目的地. 这种分立的直接商店的每个部分不会与较年轻的商店合并,但可以按任一顺序到达目的地。 MOVDIRI指令的可用性表现为CPUID特征旗MOVDIRI的存在(叶 07H中的ECX注册号的位27,参见Intel(R)64和IA-32架构软件开发者手册第2A卷中的"CPUID-CPU识别").

## 行动

```text
DEST := SRC;
```

## Intel C/C++ 内在编译器

```c
MOVDIRI void _directstoreu_u32(void *dst, uint32_t val) MOVDIRI void _directstoreu_u64(void *dst, uint64_t val);
```
